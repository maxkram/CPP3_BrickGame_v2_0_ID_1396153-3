1. **Почему MVC, а не MVP/MVVM?** Задание явно требует MVC. В отличие от MVP
   у нас нет presenter'а с интерфейсом к view: view сам опрашивает состояние
   через контроллер (тонкий, только делегирует).
2. **Почему контроллер «тонкий»?** Вся логика в модели; контроллер лишь
   пробрасывает вызовы — это проверено тестами делегирования.
3. **Как view получает данные без логики?** Таймер GTK (33 мс) вызывает
   `updateCurrentState()`, копирует `GameInfo_t` (поле, очки, уровень,
   pause) и перерисовывает drawing area. В view нет игровой логики — только
   отрисовка и маппинг клавиш в `UserAction_t`.
4. **Почему GTK+, а не Qt?** Разрешены обе библиотеки; GTK+ 3 доступен в
   учебном окружении. АПИ C, вызывается из C++.
5. **Как хранится рекорд?** В файле `~/.brickgame_snake_highscore`
   (у тетриса — свой файл). Читается при старте, обновляется в ходе игры,
   сохраняется при изменении. Для одного числа файл проще и надёжнее СУБД.
6. **Как проверена победа при длине 200, не делая 200 ходов?** Тестовый класс
   `SnakeModelTest` — `friend` модели: расставляет змейку/яблоко напрямую,
   один шаг — победа. Так же детерминированно тестируются уровни, самоудар,
   запрет разворота, ускорение.
7. **Что такое `GameInfo_t.field` как `int**`?** Требование спецификации v1.0.
Внутри объекта модели — массив `field_data_[20][10]` и указатели на строки.
Это не `static`-поле класса: у каждого объекта своё поле. `GameInfo_t` копирует
указатели, а не клетки; память принадлежит модели, освобождать её нельзя.
8. **Почему `next` у змейки — `nullptr`?** «Следующая фигура» нужна тетрису;
   для неиспользуемых данных спецификация предписывает заглушки.
9. **Как змейка ускоряется?** Space передаёт `Action, true`; интервал
   движения делится на два. Нажатие само по себе не вызывает `Tick()`.
   `Action, false` возвращает обычный интервал. Стрелки не снимают удержание.
10. **Как десктоп поддерживает тетрис?** Один и тот же `GtkView` получает
    функции АПИ через `std::function` (`GtkView::Startup`): для змейки —
    вызовы контроллера, для тетриса — C-функции v1.0. Игра выбирается
    аргументом: `snake_gui tetris`.
11. **Как обеспечен RAII?** Контейнеры и потоки владеют ресурсами,
    `GtkApplication` обёрнут в `unique_ptr` с deleter `g_object_unref`.
    Виджетами владеет дерево GTK; `GtkView` создаётся через `new`, удаляется
    по сигналу destroy, его деструктор удаляет таймер. Поэтому утверждение
    «ручного управления памятью нигде нет» неверно. Модель некопируемая:
    иначе внутренние указатели снимка указывали бы в исходный объект.
12. **Какие цели Makefile?** `all`, `install`, `uninstall`, `clean`, `dvi`,
    `dist`, `test`; дополнительно `gcov_report`, `style`, `valgrind`.


1. **Сколько яблок нужно до победы?** 196: начальная длина 4, поле 200 клеток.
2. **Когда достигается уровень 10?** При 45 очках:
   `min(10, score / 5 + 1)`.
3. **Каковы интервалы?** Уровень 1 — 500 мс, уровень 10 — 140 мс;
   с удержанием — 250 и 70 мс. Ограничение 100 мс в формуле при разрешённых
   уровнях без ускорения фактически не достигается.
4. **Почему 33 мс GTK не скорость змейки?** Это опрос/обновление изображения;
   игровой таймер принадлежит модели и использует `steady_clock`.
5. **Почему пауза не накапливает ходы?** При смене состояния `SetState`
   сбрасывает `last_tick_`. После возобновления ждём новый интервал.
6. **Почему нельзя просто вернуть `int[20][10]` как `int**`?** Типы и схема
   адресации различаются: нужен отдельный массив указателей на строки.
7. **Почему можно войти в хвост?** Без яблока хвост освобождает клетку
   в тот же шаг; яблоко по инварианту не лежит на теле.
8. **Что даёт `extern "C"`?** C linkage, без C++-декорирования имён;
   не превращает реализацию C++ в C и не разрешает конфликт двух реализаций.
9. **Какова сложность?** Добавление головы/удаление хвоста deque — O(1),
   проверка тела — O(L), генерация яблока текущим алгоритмом — O(200·L).
   На фиксированном поле это приемлемо, но не следует называть всё O(1).
10. **Что не доказывает покрытие?** Корректность требований, отсутствие всех
    ошибок, качество утверждений и работу GUI. Нужны содержательные тесты
    и ручная проверка интерфейсов.
