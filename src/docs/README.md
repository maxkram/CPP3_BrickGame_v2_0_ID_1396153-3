## Описание проекта

Реализована игра «Змейка» из серии BrickGame v2.0. Проект состоит из двух
основных частей:

1. **Библиотека логики** (`src/brick_game/snake`) — реализует правила игры,
   формализованные **конечным автоматом (КА)**. Классы находятся в пространстве
   имён `s21`. Библиотека предоставляет как C++-классы (`Model`, `Controller`),
   так и C-совместимый АПИ по спецификации BrickGame v1.0:
   `userInput()` и `updateCurrentState()`.

2. **Интерфейсы**:
   - **десктопный GUI** (`src/gui/desktop`) на **GTK+ 3** — окно с игровым
     полем 10×20 и боковой панелью; поддерживает и «Змейку», и «Тетрис»
     из BrickGame v1.0 (запуск: `snake_gui [tetris]`);
   - **консольный интерфейс** (`src/gui/console`) на **ncurses** — работает
     через C-АПИ библиотеки и полностью поддерживает игру «Змейка».

Игровое поле — матрица **10 × 20** «пикселей». Каждый элемент может быть пустым
(0), телом змейки (1) или яблоком (2).

## Архитектура MVC

Проект реализован по паттерну **MVC** (Model-View-Controller).

- **Model** — `s21::Model` в `brick_game/snake/model.h`. Содержит всю
  бизнес-логику: конечный автомат, движение змейки, столкновения, очки,
  уровни, хранение рекорда. Не содержит кода интерфейса.
- **Controller** — `s21::Controller` в `brick_game/snake/controller.h`.
  Тонкий слой: только делегирует вызовы модели. Не содержит бизнес-логики.
- **View** — `s21::GtkView` в `gui/desktop/gtk_view.h`. Только отрисовка и
  ввод. Клавиши преобразуются в действия `UserAction_t` и передаются
  контроллеру; периодический таймер (~30 кадров/с) вызывает
  `UpdateCurrentState()` и перерисовывает поле.

Правила MVC соблюдены:

- в коде представления нет бизнес-логики;
- в модели и контроллере нет кода интерфейса;
- контроллер «тонкий» (только вызовы модели).

Десктопный интерфейс получает функции ввода, снимка состояния и флагов
через `std::function`: для Snake они делегируют `Controller`, для Tetris —
C-API. Параметры представления включают next и передачу отпускания Action.
Правила игры остаются в библиотеках.

## Конечный автомат

Логика игры формализована конечным автоматом с состояниями:

| Состояние    | Описание                                                     |
|--------------|--------------------------------------------------------------|
| `Start`      | ожидание нажатия кнопки «старт»                              |
| `Spawn`      | создание змейки (4 «пикселя») и яблока                       |
| `Moving`     | основной игровой цикл: движение по таймеру, обработка ввода  |
| `Pause`      | пауза                                                        |
| `GameOver`   | завершение игры: победа или поражение                        |
| `Exit`       | выход из приложения (обрабатывается интерфейсом)             |

Переходы:

- `Start` → `Spawn` — по действию `Start`;
- `Spawn` → `Moving` — при следующем `UpdateCurrentState()`, без ожидания интервала;
- `Moving` → `Pause` — по действию `Pause`;
- `Pause` → `Moving` — по действию `Pause`;
- `Moving` → `GameOver` — столкновение со стеной или собственным телом
  (поражение) либо достижение длины 200 (победа);
- `GameOver` → `Spawn` — по действию `Start` (рестарт);
- Из любого состояния интерфейс может закрыть приложение (`Exit`);
  это не состояние `Model::State`, `Terminate` в модели Snake не меняет FSM.

Диаграмма КА — [fsm.svg](fsm.svg).

В коде состояния представлены перечислением `s21::Model::State`, переходы
выполняются в `UserInput()` и `UpdateCurrentState()`. Особое внимание в тестах
уделено проверке состояний и переходов КА.

## Механики игры

- Змейка движется самостоятельно на один блок вперёд по истечении игрового
  таймера.
- Съедание яблока увеличивает длину на один.
- При длине 200 единиц игра завершается **победой**.
- Столкновение с границей поля или собственным телом — **поражение**.
- Направление меняется стрелками; змейка может поворачивать только налево или
  направо относительно текущего направления (разворот на 180° запрещён).
- Удержание кнопки действия (`Action`, Space) **ускоряет** движение.
- Начальная длина змейки — 4 «пикселя», стартовая позиция — центр поля,
  направление — вправо.
- Поле: 10 «пикселей» в ширину и 20 в высоту.

### Реализация движения

Один шаг (`Model::Tick`): вычисляется новая позиция головы в зависимости от
направления; проверяется выход за границы поля и столкновение с телом
(клетка хвоста исключается из проверки, так как при движении без роста хвост
уходит следом за головой); голова добавляется в начало очереди; если съедено
яблоко — длина увеличивается, иначе хвост удаляется.

### Ускорение и скорость

Интервал движения зависит от уровня:

```
интервал = 500 - (уровень - 1) * 40 мс, минимум 100 мс
```

При зажатой кнопке действия интервал делится пополам.

## Очки, рекорд и уровни

- Съедание яблока даёт **1 очко**.
- **Рекорд** (максимальное количество очков) хранится в файле
  `~/.brickgame_snake_highscore` и сохраняется между запусками программы.
  Рекорд обновляется во время игры, если текущий счёт его превышает.
- **Уровень** повышается каждые **5 очков**, максимальный уровень — **10**.
  Повышение уровня увеличивает скорость движения змейки.

Информация об очках, рекорде, уровне и скорости выводится в боковой панели
интерфейса. Для неиспользуемой в змейке информации (следующая фигура) в
`GameInfo_t` предусмотрена заглушка (`next == nullptr`).

## Игра «Тетрис» (BrickGame v1.0)

В проекте также реализован Тетрис по заданию BrickGame v1.0: библиотека на
**C (C11)** со структурным подходом в `src/brick_game/tetris` и терминальный
интерфейс на **ncurses** в `src/gui/cli`.

### Конечный автомат тетриса

Состояния: `Start → Spawn → Moving ⇄ Pause → Game Over`. Диаграмма:
[docs/fsm_tetris.svg](fsm_tetris.svg).

- `Spawn` — создание новой фигуры: текущая = предыдущая «следующая»,
  генерируется новая «следующая». Если фигура не может появиться (верх поля
  занят) — переход в `Game Over`.
- `Moving` — обработка ввода (Left/Right — сдвиг, Action — поворот,
  Down — мгновенный сброс) и движение по таймеру. Касание дна или другого
  блока — фиксация фигуры и возврат в `Spawn`.
- `Game Over` — рестарт по кнопке Start.

### Механики тетриса

- все 7 тетрамино (I, O, T, S, Z, J, L), повороты по часовой стрелке;
- горизонтальное движение, ускорение падения (сброс до дна по Down);
- отображение следующей фигуры в боковой панели;
- разрушение заполненных рядов: 1 ряд — 100, 2 — 300, 3 — 700, 4 — 1500 очков;
- уровень растёт каждые 600 очков (максимум 10) и увеличивает скорость;
- рекорд хранится в `~/.brickgame_tetris_highscore` между запусками.

Тесты — `tests/test_tetris.cpp` (GTest), покрытие см. `make gcov_report`.

## Сборка и запуск

Требования: `g++` с поддержкой C++20, `pkg-config`, `libgtk-3-dev`,
`libncurses-dev`, `libgtest-dev`, `lcov`, `clang-format`.

```sh
cd src

make all         # сборка GUI и консольной версии
make test        # запуск unit-тестов
make gcov_report # отчёт о покрытии (build/report/index.html)
make dvi         # документация (build/dvi)
make dist        # архив исходников brickgame_v2_0.tar.gz
make install     # установка в $(HOME)/brickgame_v2_0
make uninstall   # удаление
make clean       # очистка
```

Запуск:

```sh
./build/snake_gui           # десктопный интерфейс (GTK+ 3), змейка
./build/snake_gui tetris    # десктопный интерфейс (GTK+ 3), тетрис
./build/snake_console  # консольный интерфейс (ncurses), змейка
./build/tetris_cli     # терминальный интерфейс (ncurses), тетрис
```

### Управление (змейка)

| Клавиша | Действие                          |
|---------|-----------------------------------|
| ← ↑ → ↓ | смена направления движения        |
| Space   | ускорение (зажать и держать)      |
| Enter   | старт / рестарт                   |
| P       | пауза                             |
| Q / Esc | выход из приложения               |

### Управление (тетрис)

| Клавиша | Действие                          |
|---------|-----------------------------------|
| ← →     | сдвиг фигуры                      |
| Space   | поворот фигуры                    |
| ↓       | мгновенный сброс фигуры вниз      |
| Enter   | старт / рестарт                   |
| P       | пауза                             |
| Q / Esc | выход из приложения               |

## Тестирование и покрытие

Unit-тесты (`tests/test_snake.cpp`) написаны на **GoogleTest**. Особое внимание
уделено проверке **состояний и переходов конечного автомата**:

- начальное состояние и переход `Start → Spawn → Moving`;
- переходы `Moving ⇄ Pause`;
- завершение игры (`GameOver`) при поражении (стена/самоудар) и победе
  (длина 200);
- рестарт из `GameOver`;
- изменение направления (повороты налево/направо, запрет разворота);
- движение по таймеру и ускорение при удержании `Action`;
- съедание яблока (рост длины, очки), уровни и скорость;
- сохранение и загрузка рекорда из файла;
- C-АПИ (`userInput`, `updateCurrentState`) и тонкость контроллера.

Для детерминированной проверки всех веток логики тесты используют
вспомогательный класс `s21::SnakeModelTest` — друга модели, имеющий доступ к
приватному состоянию (`friend`). Это позволяет расставлять змейку и яблоко
точно и проверять даже «длинные» сценарии (например, победу при длине 200).

Текущее покрытие **не измерено в среде аудита**. Требование — минимум 80 %
для библиотеки Snake. Запустите `make gcov_report` на Linux: общий HTML
и отдельная сводка Snake (`build/cov/snake.info`). Старые числа
94,8 %/95,6 % нельзя использовать без актуального отчёта.
